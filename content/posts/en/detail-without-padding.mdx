“The replies feel too simple” is concrete feedback without a direct parameter. Someone may want background, an example or a reading recommendation. Doubling the word limit enlarges the container without deciding what belongs inside it.

Field Agent originally limited responses to around 200 Chinese characters, compressing many questions into a single overview paragraph. That limit needed relaxing. The next question was how fuller answers could remain useful.

## Match depth to the question

“Who is the author?” and “Explain the author's technical focus in detail” ask for different depths. One establishes an introduction; the other explores relationships between capabilities. Giving both the same length makes the first feel laborious while the second may still miss its point.

A better default begins with a direct answer, then develops relevant aspects. An introduction can explain the purpose, main content and reading entrances. A technical explanation can cover process, choices and constraints. A recommendation can give a reason instead of merely listing a title.

The question should determine those aspects. Applying “background, advantages, scenarios, conclusion” to every reply makes direct questions sound like marketing copy. Structure should reduce the effort of understanding, rather than demonstrate that an answer looks complete.

## Length is guidance, not an achievement

The current prompt allows introductions, explanations and recommendations to reach about 300–600 Chinese characters when evidence supports that depth, with more room for explicitly detailed questions. This range guides reading effort; it does not require filling the lower bound every time.

If the evidence consists of one project introduction, the answer should stay within what it establishes. Rephrasing the same sentence four times and adding generic significance produces more text without giving the reader more information to check.

Increasing information requires better source coverage. Alongside a short biography, the index should include the author's public Agent workflow and full-stack capability descriptions. Then the answer can distinguish retrieval, tools, interfaces, server work and delivery instead of repeatedly saying “AI and full stack.”

## Preserve the owner and scope of a detail

Richer evidence makes attribution more important. Capabilities on an author page do not establish that every project implements them. Turning “familiar with multi-agent orchestration” into “this project has completed automatic multi-agent collaboration” replaces source organisation with an invented result.

A detailed explanation must preserve its subject, scope and status. Is this an author's capability or a project's implementation? Local verification or public availability? A direction being explored or a finished feature? These distinctions often matter more than adding another technical term.

Unpublished personal facts cannot be inferred from other fields either. A site name is not a legal name, and a technical role establishes neither gender nor employment history. When the question does not ask for those missing details, the answer need not end with a list of unavailable facts. Explain the evidence that exists.

## Make longer answers readable

Streaming brings text into view earlier, but paragraphs still need organisation. Answer the central question first, then use short paragraphs or a few headings. Give each section one point so the reader can judge whether the response is relevant before it has finished.

Sources should help continue that reading. Hiding inline citation numbers leaves article-title cards below the text. The reader can move from the answer to an actual page without hunting for a number between sentences.

A fuller answer does not require more enthusiastic language or an automatic follow-up question. A useful standard is simple: compared with the original sentence, does the reader understand another relationship, know a concrete approach or see more clearly where to go next?
