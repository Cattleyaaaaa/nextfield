## 后续发布步骤

1. 完成 Cloudflare 认证，确认操作对象为 `nextfield-personal-site`；提交准备发布的源代码及新文章。可在本机交互终端使用 `npx cross-env XDG_CONFIG_HOME=.wrangler wrangler login` 完成认证，或在发布进程配置有相应权限的 `CLOUDFLARE_API_TOKEN`。
2. 查询现有 Secret 名单。缺少 `DEEPSEEK_API_KEY` 时，通过交互式命令配置，避免在命令参数或日志中写入密钥：

   ```powershell
   npx cross-env XDG_CONFIG_HOME=.wrangler wrangler secret list
   npx cross-env XDG_CONFIG_HOME=.wrangler wrangler secret put DEEPSEEK_API_KEY
   ```

3. 确认 `DEEPSEEK_MODEL`，在 `wrangler.jsonc` 中启用 `FIELD_AGENT_ENABLED=true`；核对现有 Supabase 和 Analytics 配置。
4. 在具备本地音频的工作区构建并发布：

   ```powershell
   npm run typecheck
   npm run deploy
   ```

   发布命令会重新生成索引、执行 Cloudflare 构建，并随 Worker 发布限流类和迁移。

5. 正式域名验收：助手状态、流式问答、来源跳转、内容卡片、问题预填、双语、手机、键盘、关闭动效、五次额度、跨实例共享计数，以及电台拖动和站内切换播放。

## 回退

助手服务异常时将 `FIELD_AGENT_ENABLED` 改回 `false` 并重新部署。内容、来源卡片和浏览入口仍可使用；现有匿名额度存储不必清空。整个版本需要回退时使用先前 Worker 版本，保留已创建的 Durable Object 迁移记录，避免把迁移当作普通配置删除。

发布前版本为 `266b5723-8048-41d8-a078-0f8339ed7cb5`。回退涉及新建 Durable Object 绑定时，应先确认平台对版本与迁移的兼容性；关闭助手开关是较小范围的回退方式。
